Glob finds files, Grep finds lines

Objective 13 on your score report came back 50%.

The exam guide gives each of the six built-in tools one job (task statement 2.5). This lesson covers two of them, which do similar-sounding jobs, and the order you use them in when you don't know a codebase. The Claude Code docs sum up the split in one line: "Where Glob finds files by name, Grep finds lines inside them." (Tools reference)

Ask what you already know about the thing you're looking for. If you know its file name, use Glob. If you know some text inside the file, use Grep.

Two tools, two kinds of match

Glob only looks at paths. It never opens a file, so it can't tell you whether a file contains anything. Grep opens files and matches lines. Its default output is just the paths of matching files, and it shows the matching lines only when asked (output modes).

The word-overlap trap. "Find the config files" and "find where config is loaded" both say config. The first is a name, so use Glob (**/*config*). The second is behaviour in the code, so use Grep (loadConfig). A Glob for *refund* finds refund_service.py and misses checkout.py, which calls calculateRefund().

You can also combine them. Grep takes a file filter, so "the error text, but only in Python files" is a single Grep scoped to *.py, not a Glob followed by reading every match.

The exploration loop: search narrow, then read

The second half of the objective is "under context-window constraints". Every file you Read takes up context space. The guide's skill statement is to build understanding incrementally: begin with Grep to locate entry points, then use Read to follow imports and trace the flow, instead of reading every file first.

  1. Grep for something concrete: a route string, an error message, a function name. You get back a short list of files.
  2. Read only those hits.
  3. Follow what you find there (an import, a call), then Grep again for the next name.
  4. Stop when you can answer the question. You'll never have read most of the repo, and you didn't need to.

Wrapper modules. Sometimes utils/index.ts re-exports fmt under the name formatDate. Grepping for fmt then misses every caller that imports formatDate. The guide's move is to "first identify all exported names, then search for each name".

At exam time. Options that say "read every file", "read the whole directory first" or "load the repo into context" fail the context requirement, even though they're complete (the Lesson 8 grid: complete ✓, within context ✗). An option that Globs a name pattern to find callers fails the other way, because callers aren't named after what they call. The key is nearly always a narrow Grep followed by Read.

Not needed for the exam, but true: Grep skips gitignored files and Glob doesn't by default. Results from Glob are sorted by modification time and capped at 100. Grep uses ripgrep regex, so interface{} has to be escaped. On recent Claude Code builds for macOS and Linux, Glob and Grep are left out of the default tool set and Claude runs find and grep through Bash instead. The exam guide still treats them as built-in tools, so answer the way the guide does. (Tools reference, fetched 2026-10-08)
