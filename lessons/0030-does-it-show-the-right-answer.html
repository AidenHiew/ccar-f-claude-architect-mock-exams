Does it show Claude the right answer?

In late October you lost 3 questions in a row the same way: Claude's output was wrong, the developer knew the right output, and you picked a test or a check over showing Claude the right output. This page shows all 3 in full, plus 1 question from the other topic (4.2). You don't need to remember any of them.

3.5 is the exam guide's topic number for improving Claude's work round by round in Claude Code (the official guide lists what the exam tests). 4.2 is putting examples in a prompt. They are your last 2 weak topics.

The plain question. When Claude keeps getting an answer wrong and you know the right answer: does this option show Claude the right answer, or does it only tell Claude it got it wrong?

An everyday example. A new cashier keeps giving the wrong change.

  • You could check: "Is the change made of coins and notes?" Every wrong answer passes. The check is real, but it can't spot the problem.
  • You could say "wrong" each time. Now the cashier knows that it's wrong, but still not what right is.
  • Or you show them: "$20 for a $13.40 bill: $6.60 back. $10 for $7.25: $2.75 back." Now they can see the pattern.
The one idea: if the right outputs are known and words keep failing, pick the option that hands Claude real inputs with their exact right outputs, for the inputs that are going wrong.
  • A check on the shape (a valid code, a format pattern, all fields filled) passes on wrong answers.
  • Tests on inputs that already work miss the problem.
  • Tests first are right when there are many listed cases or a speed target: then you need a check you can re-run after every new version.

Words to start with

Stem
The question's own text, above the four options.
Input/output examples
A few real inputs, each with the exact output it should become. They show Claude the change instead of describing it.
A check on the shape
A test that looks at what kind of output it is, not whether it is the right one: "is it one of the 8 codes?", "does it match the format pattern?", "are all 3 fields filled?" A wrong answer of the right kind passes.
Tests first, share the failures
Write a set of automatic checks for what the code must do before Claude changes it. Run them on each new version and paste the failures back to Claude, until all pass.
Regular expression
A pattern that text must match, such as "letter, digit, dash". It checks the format only.
JSON schema check
A check that the output has the right fields of the right types. Again, the shape only.
Prose
Ordinary written sentences, here: describing the format in words.

Words that appear in the past questions (you need these only to read them):

  • Carrier: a delivery company. Tracking update: a status message such as "OUT FOR DEL" (out for delivery). Status code: the company's own fixed label for each status.
  • Bay: a section of library shelving. flr: floor.
  • Pre-existing condition: an illness a pet had before its insurance began. Assessor: a person who checks insurance claims. Overturn: decide the flag was wrong.

Ask three things of each option, in this order:

  1. Does the stem say the right outputs are known? ("has the correct result", "knows the right code", "knows the right split")
  2. Does this option contain them? Real inputs, each with its exact output. A check on the shape doesn't.
  3. Is it about the inputs that are going wrong? Not the ones that already work.

A developer asked Claude for a function that turns free-text shelf locations from 9 branches, such as "2nd flr, bay 14 L" and "Level 2 / Bay 14 / left", into one standard format. After 3 rounds of describing the target format in prose, each new version still formats some branches' locations differently. The developer has the correct result for each branch's style of location. What should they give Claude next?

✗ Your pick: DA test that checks each output matches the format's regular expression
✓ Correct: C3 raw locations, each with the exact output the function should return
The other two options (A, B)
  • AA longer prose description of the target format, part by part
  • BQuestions from Claude about each branch before it rewrites the code
Where it went wrong:
  • The two clues: words have failed 3 times, and the developer already has the right result for each style. So what Claude is missing is a picture of the right answer.
  • The test (your pick) checks that each output matches the format. A location can match the format exactly and still say "right" when the shelf is on the left. The test can say pass or fail; it can't show Claude which answer is right.
  • C hands Claude 3 real locations with the exact output each should become. That is the right answer, shown.

Weak Rows Paper 6, question 1

A developer asked Claude for a function that maps tracking updates from 6 carriers, such as "OUT FOR DEL" and "With driver - final mile", to the company's 8 status codes. After 2 rounds of prose corrections, each output is one of the 8 codes, but about 1 in 10 is the wrong one, and which carriers go wrong changes with each version. The developer knows the right code for each carrier's updates. What should they give Claude next?

✗ Your pick: AA test that checks each result is one of the 8 valid status codes
✓ Correct: C4 raw carrier updates, each with the exact status code it should map to
The other two options (B, D)
  • BA fuller prose description of what each of the 8 status codes means
  • DQuestions from Claude about each carrier before it rewrites the map
Where it went wrong:
  • Same shape as the shelf-location card above (26 Oct), one day later. The stem even tells you the check would pass: every output is already one of the 8 codes.
  • The test (your pick) asks "is this a valid code?" The wrong outputs are valid codes, just the wrong ones. So the test passes on exactly the answers you need fixed.
  • C gives 4 real updates, each with the exact code it should become. That carries the knowledge the developer has and Claude lacks.

Weak Rows Paper 6, question 7

A developer asked Claude Code for a function that splits the owner name on each claim form, such as "Dr and Mrs J. Okafor" or "Okafor, Jane (Ms)", into title, first name and surname. After 2 rounds of prose corrections, about 1 in 8 names still splits wrongly, mostly the less common styles, though each result has all 3 fields filled. The developer knows the right split for each style. What should they give Claude next?

✗ Your pick: DTests for the 2 most common name styles, then share the failures
✓ Correct: A3 raw names, each with the exact title, first name and surname
The other two options (B, C)
  • BA JSON schema check that each result fills all 3 name fields
  • CA longer prose description of how each name style should split
Where it went wrong:
  • This time the test option did carry real answers, but for the wrong names. The wrong splits are "mostly the less common styles"; tests on the 2 most common styles check names that already work.
  • A gives 3 names with their exact title, first name and surname. Pick the 3 that are going wrong and Claude sees exactly what right looks like for them.
  • B, the schema check, is the same trap as the valid-code test in the carrier card (Weak Rows Paper 6, question 1): every result already fills all 3 fields, so the wrong splits pass it.
The check: if an option is a test, ask "would the wrong outputs in the stem pass it?" If they would, it can't fix them. If the stem says the developer knows the right answers, look for the option that writes them down.

Part 2 · When tests first are right (3.5)

This is the other side of the line: when tests first beat examples.

The stem saysPickWhy examples lose
Many listed cases (for example, 11 pricing rules a team has written down) plus a speed target (for example, the function must answer within 50 milliseconds)Write tests for the cases and the speed first, then share failures each round3 examples can't cover 11 rules, and an example never measures speed.
Words keep failing, the right outputs are known, a few styles go wrong2–3 inputs with their exact outputs—

One more point: a test that does carry an exact output is really an input/output example written as a test. The exam guide lists test cases that pair a concrete input with its expected output as a fix for edge cases (unusual inputs the code mishandles), for instance a migration script (a script that copies data from an old table into a new one) that mishandles empty (null) values. So don't reject an option for saying "test". Reject it if it only checks the shape, or if it checks the wrong inputs.
