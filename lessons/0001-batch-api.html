The Batch API decision

One question decides every Batch-vs-synchronous exam item — and it's the one you skipped twice.

On the exam, Batch API questions look like cost questions. They aren't. They're latency questions wearing a cost disguise. Both times this beat you — diagnostic Q23 and today's mock — you took the 50% savings bait and reached for machinery to keep the speed. This lesson installs the single decision that makes these questions automatic.

The whole lesson in one line: Is a human or a caller waiting on this result? Yes → synchronous. No → Batch. There is no third option that gives you batch pricing without the wait.

What the Batch API actually trades

It trades immediacy for cost. You hand Anthropic a pile of requests, it processes them asynchronously, and you collect results later. Here are the numbers — verified against the official docs, not memory:

Read the fact that matters most slowly: there is no latency guarantee. "Usually under an hour" is a description, not a promise — the ceiling is 24 hours, and demand can push you there. So the moment a result is on someone's critical path, batch is disqualified. Not "risky." Disqualified.

Why "Batch it, with a fallback" is always wrong

Your answer both times was some form of "move it to Batch and add a timeout that falls back to synchronous." It feels clever — savings plus a safety net. It is the over-engineered distractor, and here is the tell:

The machinery doesn't remove the wait — it just moves it. A blocking check that falls back to sync after a batch runs long has now made the developer wait longer (batch delay, then a full sync call) to save nothing on the calls that matter. You've added a polling-and-timeout system to arrive at "just call it synchronously." The designed answer was already there: if the caller waits, keep it synchronous.

This is your recurring pattern in one instance (see learning record 0003): when two options both seem to work, the elaborate one is bait. The exam rewards matching each workload to the right API — nightly report → Batch, blocking check → sync — not building a hybrid.
