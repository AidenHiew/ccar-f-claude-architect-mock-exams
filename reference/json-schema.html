JSON Schema

A schema is a contract about the shape of data, not its truth. Taught in Lesson 11.

Keywords

type
object · array · string · number · integer · boolean · null
properties
The fields an object may contain, each with its own schema
required
Keys that must appear. Not listed means the key is optional (may be omitted)
["string","null"]
Nullable: the key appears and null is a legal value
enum
A fixed list of allowed values. Add "unclear" for ambiguous cases and "other" + a detail string for unforeseen ones
additionalProperties
false means no fields beyond properties; Claude's structured outputs require false on objects

Where it goes in a Claude request

tools[].input_schema
The tool-call arguments. An extraction tool's output shape
strict: true
On a tool: its input schema is enforced
output_config.format
{type: "json_schema", schema}: Claude's reply is valid JSON in a text block
--json-schema
Claude Code, with -p --output-format json: structured CI output
tool_choice
Not a schema. It decides whether a tool must be called (auto / any / named tool)

What it guarantees

ErrorStopped by the schema?
Bad JSON syntax, wrong type, missing required key✓ eliminated
Fields that don't agree (line items ≠ total)✗ your code, then retry with the error
Right type, wrong field (vendor put in customer)✗ your code or a reviewer
Invented value for a field the document lacks✗ fix the design: make it nullable

Also not guaranteed: output cut off at stop_reason: "max_tokens", a refusal, and enum capitalisation (compare enum values case-insensitively).

Required + non-nullable + sometimes-absent data = forced fabrication. Give the model a legal way to say "not there".
