Batch API

Message Batches API — the memorize-these facts and the one decision rule.

If…Then…
A caller / human is waiting on the resultSynchronous API
Nothing waits — overnight, weekly, bulk evalBatch API (−50%)
"Get the saving but keep it fast"Trap — no such option; keep it sync

Hard facts

cost
50% cheaper (input + output) than the standard API.
latency
Most batches < 1 hour, but no SLA; hard cap 24 h, then unsent requests expire (unbilled).
correlate
custom_id (1–64 chars). Results return in any order — always match by custom_id, never array position.
limits
≤ 100,000 requests or 256 MB per batch, whichever first.
retention
Results downloadable for 29 days after creation.
failures
Per-request status: succeeded, errored, canceled, expired. Resubmit only the failed items (found via custom_id).
shape
One request → one response, async. No agentic tool loop inside a single batch request (can't execute a tool and feed the result back mid-request).

Exam tells

"developer waits / pre-merge / blocking" in the stem → synchronous. "nightly / weekly / overnight / bulk" → Batch. Any option offering batch pricing + a fallback/polling/timeout to stay fast is the over-engineered distractor.
