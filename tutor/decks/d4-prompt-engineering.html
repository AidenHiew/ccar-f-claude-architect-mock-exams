The through-line · read this twice

When two options both seem to work, pick the designed mechanism — not machinery, and not "tell the model to try harder."

Structural and deterministic beats probabilistic. A schema keyword, a config expansion, or one feedback line beats a new service or a sterner instruction. This single idea explains all three of your D4 misses.

4.1 · Explicit criteria

Cut false positives with categories, not confidence

A model's self-assessed confidence is not calibrated. "Be conservative" and "only report high-confidence findings" do not improve precision.

Trap

"Report only issues you're highly confident about."

Doubles down on the uncalibrated signal that already failed.

Instinct

Name the categories: report bugs & security, skip style & local patterns.

A noisy category poisons trust in accurate ones — disable it while you fix its prompt.

4.2 · Few-shot prompting

Show 2–4 examples — with the reasoning

When detailed instructions still produce inconsistent output, targeted examples are the strongest fix. Examples that show why one action beats the alternatives let the model generalize judgment to new inputs.

Trap

Rewrite the prose longer and more precise; enumerate every case you've seen.

More prose is still prose; enumeration only pattern-matches the past.

Instinct

2–4 input→output pairs for the ambiguous cases, each showing the reasoning.

Fixes format drift, null-on-odd-formats, and extraction hallucination.

4.3 · Structured output you missed this · Q21

Required fields make the model fabricate

A required field for data that may not exist forces the model to invent a plausible value. Make genuinely-absent fields nullable / optional so null is a legal answer.

Trap

Tell the model to write the string "NONE" when the PO number is missing.

Sentinel leaks into downstream data and still fights required.

Instinct

Make po_number nullable in the schema.

Enums: add "unclear" / "other". And remember — tool_use kills syntax errors, never semantic ones.

You picked B — the "NONE" instruction. That's fixing a schema problem at the prompt layer. The schema is the mechanism.

4.4 · Validation & retry you missed this · Q22

Retry = resend with the error attached

A useful retry sends the document plus the failed extraction plus the specific validation error, so the model can self-correct the exact failure. Format and structural errors are precisely what this fixes.

Trap

Strip the failing field from the schema, then re-add it in a later pass.

A two-pass pipeline redesign for something one feedback line fixes.

Instinct

Resend with the validation error appended.

Limit: retries fix format/structure — they cannot conjure information that isn't in the document.

You picked D — schema surgery. Reach for the one-line feedback loop before rebuilding the pipeline.

4.6 · Multi-instance review

A model can't review its own work

The instance that generated the code keeps its reasoning context and won't seriously question its own decisions. Stronger prompts and more thinking budget don't fix this — the bias is contextual.

  • Dispatch an independent instance with no generation context for the review. Fresh eyes catch the concurrency bug the author approved.
  • Large PRs: per-file passes for local issues + a separate cross-file integration pass. Fixes attention dilution.
  • A bigger context window does not fix attention quality. Consensus voting can suppress real intermittent catches.
